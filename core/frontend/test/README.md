# 控制台测试

```bash
npm test          # 跑一遍
npm run test:watch
```

vitest + jsdom，不需要浏览器。

## 测什么

控制台这一侧只承担一件要紧的事：**插件被启用或禁用时，菜单和已经打开的页面要跟着变**。Core 那一侧（下发的菜单树会变）有自己的测试；这里测的是浏览器拿到变化之后做了什么。

具体是两块：

`pluginRegistry.js` 的 `resolveEntry` —— 把一个控制台 URL 映射到该挂载哪个微前端。容易错的地方是路径匹配：最长前缀要赢（否则子路由会挂载父插件的应用，而且不会报错，只是显示了错的东西），分组节点不能被挂载，`/note` 不能匹配 `/notes`。

`AppView.vue` 的挂载生命周期 —— 用 `loadMicroApp` 手工管理而不是 `registerMicroApps`，因为后者注册后无法注销，被禁用的插件会一直占着路由直到刷新页面。这里的测试用一个假的 qiankun，只记录挂载和卸载：重点从来不是子应用渲染了什么，而是它有没有被撤下来。

## 验证测试有效性

和 Go 那边一样的做法：把行为弄坏，看有没有测试失败。

最近一次 —— 删掉 `AppView.vue` 里的 `watch(() => registry.version, sync)`（也就是让注册表变化传不到已打开的页面），3 个测试失败。那一行正是「禁用插件后页面立刻消失」成立的原因。


## 为什么组件要真的渲染一次

`plugins.test.js` 写出来的第一次运行就发现插件管理页是坏的：配置行的 `<tr>` 落在 `v-for` 外面，那里的 `p` 不存在，**一渲染非空列表就抛错**。它是两轮之前随配置表单一起加进去的，`vite build` 一直通过 —— Vue 的模板编译期不检查这个,只在运行时炸。

在此之前前端只有两个测试文件，测的是 `pluginRegistry` 的纯函数和 `AppView` 的挂载逻辑。**没有任何一处真的渲染过插件列表**，所以一个每次渲染都抛的页面可以一路通过构建、被提交、被推送。

结论不是「加更多断言」，是**至少把每个页面挂载一次**。上面那个 bug 不需要精巧的用例，只需要有人 `mount()` 过它。


## pages.test.js 挂载每一个页面

断言本身不重要 —— 重要的是 `mount()` 被调用了。渲染错误无论测什么都会以抛异常的形式冒出来。

验证过一次：往 `Users.vue` 里塞一个 `{{ nonexistent.field }}`，`vite build` **照常通过**，而这个测试立刻失败。

它同时挡住另一类：路由指向的页面必须存在且能挂载。控制台曾经在导航栏上挂着「扩展管理」，指向一个所有调用都发往 `/api/system/extensions/*` 的页面 —— 那些路由在插件化改造时就没了，对应的表也已经被 `000008_drop_extension_tables` 删掉。它在导航里看起来像个功能，点进去每个操作都 404。
